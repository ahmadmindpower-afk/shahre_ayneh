# چک‌لیست آزمون و پذیرش

## شروع و ذخیره
- [ ] بازی در حالت بدون دادهٔ قبلی شروع شود.
- [ ] بارگذاری ذخیرهٔ معتبر موفق باشد.
- [ ] ذخیرهٔ خراب یا نسخهٔ ناشناخته باعث صفحهٔ خالی نشود؛ پیام و راهکار نشان داده شود.
- [ ] خروجی و بازیابی پیشرفت با نسخهٔ فعلی تست شود.

## کنترل‌ها
- [ ] کلیدهای جهت‌نما و WASD کار کنند.
- [ ] کلید فاصله و دکمهٔ تعامل به‌درستی عمل کنند.
- [ ] لمس موبایل و دکمه‌های کنترل در صفحهٔ باریک قابل استفاده باشند.
- [ ] همهٔ پنل‌ها با صفحه‌کلید پیمایش‌پذیر باشند.

## منطق مرحله
- [ ] هر مرحله شناسهٔ یکتا و ارجاع به شهر و تعارض دارد.
- [ ] همهٔ سرنخ‌ها یک بار پاداش اصلی بدهند.
- [ ] ورود به شخصیت پیش‌نیازها را بررسی کند.
- [ ] پاسخ اشتباه امکان تلاش مجدد یا ادامهٔ منطقی بدهد.
- [ ] پاسخ درست مرحلهٔ بعد را باز کند و ذخیره شود.
- [ ] پایان بازی به‌درستی نمایش داده شود.

## کیفیت محتوا
- [ ] هر سرنخ با معما و تصویر صحنه مرتبط است.
- [ ] هر گزینهٔ غلط توضیح قابل فهم دارد.
- [ ] مسئله از شواهد قابل حل است و جواب به حدس تصادفی متکی نیست.
- [ ] برای فرضیه‌های چندگانه معیار ارزیابی مشخص است.
- [ ] متن هیچ‌کس را تشخیص یا برچسب روان‌شناختی نمی‌زند.
- [ ] اطلاعات منبع یا صفحهٔ PDF برای نگاشت‌ها ثبت شده است.

## تصویر و صحنه
- [ ] هر یک از شش شهر سیلوئت و پالت متمایز دارد.
- [ ] تصویر و نام منطقه با اشیای قابل تعامل و سؤال هم‌خوان هستند.
- [ ] متن روی تصویر خواناست.
- [ ] کاهش حرکت و خاموش‌کردن صدا در دسترس است.
- [ ] هیچ سرنخ ضروری فقط با رنگ یا صدا منتقل نمی‌شود.

## انتشار
- [ ] اندازهٔ فایل و زمان بارگذاری کنترل شده است.
- [ ] نسخهٔ پشتیبان پیش از تغییر بزرگ ساخته شده است.
- [ ] متن تغییرات و ریسک‌های باز ثبت شده است.
